## 1. 임베딩 모델

### 1.1 임베딩이란?

```
텍스트 → [수치 벡터] 변환

"안녕하세요" → [0.12, -0.34, 0.89, ..., 0.23]  (1536차원)

의미적으로 유사한 텍스트 → 벡터 공간에서 가까운 위치

         벡터 공간 (2D 시각화)

         ● 개
    ● 고양이
    ● 강아지           ● 자동차
                  ● 트럭
                  ● 버스

    동물 클러스터      교통 클러스터
```

### 1.2 OpenAI 임베딩

```python
from langchain_openai import OpenAIEmbeddings

# text-embedding-3-small (추천: 속도/비용 균형)
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    dimensions=1536  # 기본값
)

# text-embedding-3-large (더 높은 정확도)
embeddings_large = OpenAIEmbeddings(
    model="text-embedding-3-large",
    dimensions=3072
)

# 단일 텍스트 임베딩
vector = embeddings.embed_query("파이썬 리스트란?")
print(f"벡터 차원: {len(vector)}")  # 1536

# 여러 텍스트 일괄 임베딩
vectors = embeddings.embed_documents([
    "파이썬 리스트",
    "파이썬 딕셔너리",
    "자동차 엔진"
])
```

### 1.3 HuggingFace 임베딩 (무료)

## 2. 벡터 저장소

### 2.1 벡터 저장소 종류 비교

```
┌─────────────────────────────────────────────────────────────┐
│  로컬 (파일 기반)           클라우드 (관리형)                  │
│  FAISS ────────────────  Pinecone                           │
│  Chroma ────────────────  Weaviate                          │
│  Qdrant (로컬/클라우드)    Qdrant Cloud                      │
└─────────────────────────────────────────────────────────────┘

FAISS:  Meta 개발, 매우 빠름, 인메모리 or 파일 저장
Chroma: 오픈소스, 영구 저장 쉬움, 메타데이터 필터링 강력
```

### 2.2 FAISS 활용

```python
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings()

# 문서로 직접 생성
vectorstore = FAISS.from_documents(
    documents=docs,
    embedding=embeddings
)

# 파일로 저장 / 불러오기
vectorstore.save_local("faiss_index")
loaded = FAISS.load_local(
    "faiss_index",
    embeddings,
    allow_dangerous_deserialization=True
)

# 유사도 검색
results = vectorstore.similarity_search(
    query="파이썬 리스트 사용법",
    k=4  # 상위 4개
)

# 점수 포함 검색
results_with_score = vectorstore.similarity_search_with_score(
    query="파이썬 리스트 사용법",
    k=4
)
for doc, score in results_with_score:
    print(f"유사도: {score:.4f} | {doc.page_content[:50]}")
```

### 2.3 FAISS 인덱스 타입

```
Flat (기본): 정확한 검색, O(n) 시간
  → 소규모 데이터 (< 10만 벡터)

IVF (Inverted File): 클러스터 기반, 빠른 검색
  → 중간 규모 (10만 ~ 100만)

HNSW (Hierarchical NSW): 그래프 기반, 초고속
  → 대규모 데이터 (100만+)
```

### 2.5 메타데이터 필터링

```python
# 특정 소스 파일에서만 검색
results = vectorstore.similarity_search(
    query="계약 기간",
    k=3,
    filter={"source": "contract_2024.pdf"}
)

# Chroma에서 복합 필터
results = chroma_db.similarity_search(
    query="임금 규정",
    k=3,
    where={
        "$and": [
            {"document_type": {"$eq": "취업규칙"}},
            {"year": {"$gte": 2023}}
        ]
    }
)
```

### 2.6 검색 방식 비교

```python
# Retriever로 변환
retriever = vectorstore.as_retriever(
    search_type="similarity",    # 기본: 코사인 유사도
    search_kwargs={"k": 4}
)

# MMR (Maximal Marginal Relevance): 다양성 보장
mmr_retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 4, "fetch_k": 20}
)

# 임계값 기반: 유사도 점수 이상만 반환
threshold_retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={"score_threshold": 0.7, "k": 4}
)
```

## 3. 배치 임베딩 최적화

```python
def batch_embed_documents(docs, embeddings, batch_size=100):
    """대용량 문서 배치 임베딩"""
    all_vectors = []
    for i in range(0, len(docs), batch_size):
        batch = docs[i:i+batch_size]
        texts = [doc.page_content for doc in batch]
        vectors = embeddings.embed_documents(texts)
        all_vectors.extend(vectors)
        print(f"진행: {min(i+batch_size, len(docs))}/{len(docs)}")
    return all_vectors
```

## 💡 핵심 포인트
- 임베딩 모델은 Indexing과 Querying에서 **동일한 모델** 사용 필수
- FAISS: 빠른 검색, 인메모리 / Chroma: 영구 저장, 메타데이터 필터 강력
- MMR 검색으로 다양한 관점의 문서 검색 (중복 최소화)
- `normalize_embeddings=True`는 코사인 유사도 계산 시 성능 향상

## ⚠️ 주의사항
- 임베딩 모델 변경 시 전체 벡터저장소 재구축 필요
- `allow_dangerous_deserialization=True` FAISS 로드 시 신뢰할 수 있는 파일만 사용
