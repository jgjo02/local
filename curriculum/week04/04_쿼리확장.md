- Multi-Query Retriever를 구현할 수 있다

## 1. 쿼리 확장의 필요성

```
문제:
  사용자 쿼리: "청약 점수 계산"
  문서 표현:   "가점제 산정 방식"
  → 의미는 같지만 표현이 달라 검색 실패!

해결 방법: 하나의 쿼리 → 여러 쿼리로 확장
  원본: "청약 점수 계산"
  확장1: "주택청약 가점제 계산 방법"
  확장2: "청약 점수 무주택기간 부양가족"
  확장3: "청약 점수 산정 공식"
  → 다양한 쿼리로 검색 → 관련 문서 찾을 확률 증가
```

## 2. Multi-Query Retriever

```python
from langchain.retrievers.multi_query import MultiQueryRetriever
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

multi_retriever = MultiQueryRetriever.from_llm(
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3}),
    llm=llm
)

# 내부적으로 LLM이 여러 쿼리 생성 후 결합
docs = multi_retriever.invoke("청약 점수 계산")
# LLM이 자동으로 3~5개 유사 쿼리 생성 후 검색
```

## 3. HyDE (Hypothetical Document Embeddings)

쿼리 대신 "가상의 답변 문서"를 임베딩으로 검색:

```
아이디어:
  쿼리: "청약 1순위 조건은?"
         ↓ LLM이 가상 답변 생성
  가상 문서: "청약 1순위가 되기 위해서는 청약통장을
              투기과열지구는 2년 이상, 수도권은 1년 이상..."
         ↓ 가상 문서를 임베딩하여 검색
  → 실제 문서와 표현이 비슷 → 더 정확한 검색!
```

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# 가상 문서 생성 체인
hyde_prompt = ChatPromptTemplate.from_template("""
다음 질문에 대한 답변이 담긴 문서 단락을 작성해주세요.
실제 문서처럼 작성하되, 확실하지 않은 내용은 일반적으로 알려진 내용으로 작성하세요.

질문: {question}

문서 단락:""")

generate_doc_chain = hyde_prompt | llm | StrOutputParser()

# HyDE 검색
def hyde_search(question: str, vectorstore, k: int = 4):
    hypothetical_doc = generate_doc_chain.invoke({"question": question})
    print(f"가상 문서: {hypothetical_doc[:100]}...")
    return vectorstore.similarity_search(hypothetical_doc, k=k)
```

## 4. RAG-Fusion

Multi-Query + RRF 결합:

```python
from langchain_core.runnables import RunnableParallel

def rag_fusion(question: str, retriever, llm, k: int = 4):
    # 1. 다중 쿼리 생성
    queries_prompt = ChatPromptTemplate.from_template(
        "'{question}'에 관련된 다른 검색 쿼리 4개를 한 줄씩 생성:\n"
    )
    queries_chain = queries_prompt | llm | StrOutputParser()
    queries_text = queries_chain.invoke({"question": question})
    queries = [question] + [q.strip() for q in queries_text.strip().split("\n") if q.strip()]

    # 2. 각 쿼리로 검색
    all_results = {}
    for q in queries:
        docs = retriever.invoke(q)
        for rank, doc in enumerate(docs):
            key = doc.page_content
            if key not in all_results:
                all_results[key] = {"doc": doc, "score": 0}
            all_results[key]["score"] += 1 / (rank + 60)  # RRF

    # 3. RRF 점수로 재정렬
    reranked = sorted(all_results.values(), key=lambda x: x["score"], reverse=True)
    return [item["doc"] for item in reranked[:k]]
```

## 💡 핵심 포인트
- Multi-Query: 하나의 질문 → 여러 표현으로 검색 범위 확장
- HyDE: 질문 → 가상 답변 문서 → 문서 임베딩으로 검색
- RAG-Fusion: Multi-Query + RRF로 최종 순위 결합
- 비용 vs 성능 트레이드오프 존재
