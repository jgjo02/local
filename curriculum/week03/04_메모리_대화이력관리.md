## 1. 대화 이력 관리의 필요성

```
메모리 없는 챗봇:
  User: "내 이름은 김철수야"
  AI:   "안녕하세요, 김철수님!"
  User: "내 이름이 뭐야?"
  AI:   "죄송합니다, 알 수 없습니다" ← 문제!

메모리 있는 챗봇:
  User: "내 이름은 김철수야"
  AI:   "안녕하세요, 김철수님!"
  User: "내 이름이 뭐야?"
  AI:   "김철수님이라고 하셨습니다!" ✓
```

## 2. RunnableWithMessageHistory (v0.3 방식)

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.chat_history import BaseChatMessageHistory, InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

# 세션 저장소
store: dict[str, InMemoryChatMessageHistory] = {}

def get_session_history(session_id: str) -> BaseChatMessageHistory:
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

# 체인 구성
prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 친절한 AI 어시스턴트입니다."),
    MessagesPlaceholder(variable_name="history"),
    ("human", "{input}")
])

llm = ChatOpenAI(model="gpt-4o-mini")
chain = prompt | llm

# 메모리 래핑
chain_with_history = RunnableWithMessageHistory(
    chain,
    get_session_history,
    input_messages_key="input",
    history_messages_key="history"
)

# 사용 - 같은 session_id면 이력 유지
config = {"configurable": {"session_id": "user_001"}}

r1 = chain_with_history.invoke({"input": "내 이름은 홍길동이야"}, config=config)
r2 = chain_with_history.invoke({"input": "내 이름이 뭐야?"}, config=config)
print(r2.content)  # "홍길동님이라고 하셨습니다"
```

## 3. 토큰 제한 관리 전략

```python
from langchain_core.messages import trim_messages

# 최근 N 토큰만 유지
trimmer = trim_messages(
    max_tokens=2000,
    strategy="last",           # "last": 최근 메시지 유지
    token_counter=llm,         # LLM으로 토큰 계산
    include_system=True,       # 시스템 메시지 항상 유지
    allow_partial=False
)

chain = trimmer | prompt | llm
```

### 전략 비교

| 전략 | 방법 | 장점 | 단점 |
|------|------|------|------|
| Buffer | 전체 이력 유지 | 완전한 컨텍스트 | 토큰 무제한 증가 |
| Window | 최근 K턴만 유지 | 예측 가능한 비용 | 오래된 정보 손실 |
| Summary | LLM으로 요약 | 긴 대화 압축 | 요약 비용 발생 |
| Token Trim | 토큰 수 제한 | 정확한 비용 통제 | 구현 복잡 |

## 4. 멀티 사용자 세션 관리

```python
# 사용자별 독립 세션
users = {
    "user_001": {"name": "홍길동", "history": InMemoryChatMessageHistory()},
    "user_002": {"name": "김영희", "history": InMemoryChatMessageHistory()},
}

def get_user_session(session_id: str):
    if session_id not in users:
        users[session_id] = {"history": InMemoryChatMessageHistory()}
    return users[session_id]["history"]

chain_with_history = RunnableWithMessageHistory(
    chain,
    get_user_session,
    input_messages_key="input",
    history_messages_key="history"
)

# user_001 세션
c1 = {"configurable": {"session_id": "user_001"}}
chain_with_history.invoke({"input": "내 이름은 홍길동"}, config=c1)

# user_002 세션 (user_001과 독립)
c2 = {"configurable": {"session_id": "user_002"}}
chain_with_history.invoke({"input": "내 이름은 김영희"}, config=c2)
```

---

## 💡 핵심 포인트
- v0.3에서는 `RunnableWithMessageHistory` + `InMemoryChatMessageHistory` 사용
- `session_id`로 사용자/대화를 분리
- 긴 대화에서는 반드시 토큰 제한 전략 적용

## ⚠️ 주의사항
- `InMemoryChatMessageHistory`는 서버 재시작 시 초기화
- 프로덕션에서는 Redis, PostgreSQL 등 외부 저장소 사용
