# 3차시: 사용자 정의 도구 (Custom Tools)

## 학습 목표
- @tool 데코레이터로 커스텀 도구를 생성할 수 있다
- Pydantic으로 입력 스키마를 정의할 수 있다
- 비동기 도구를 구현할 수 있다

## 1. @tool 데코레이터

가장 간단한 커스텀 도구 생성 방법:

```python
from langchain_core.tools import tool
from typing import Optional

@tool
def search_korean_law(query: str) -> str:
    """한국 법령을 검색합니다. 법령 제목이나 조문 내용으로 검색하세요."""
    # 실제 구현에서는 법제처 API 호출
    return f"'{query}' 관련 법령 검색 결과: 민법 제750조..."

@tool
def calculate_statute_of_limitations(incident_date: str, law_type: str) -> str:
    """소멸시효를 계산합니다.

    Args:
        incident_date: 사건 발생일 (YYYY-MM-DD)
        law_type: 법률 종류 (민사/형사/행정)
    """
    from datetime import datetime, timedelta
    date = datetime.strptime(incident_date, "%Y-%m-%d")

    periods = {"민사": 10, "형사": 5, "행정": 3}
    years = periods.get(law_type, 5)

    expiry = date.replace(year=date.year + years)
    remaining = (expiry - datetime.now()).days

    return f"{law_type} 소멸시효: {expiry.strftime('%Y-%m-%d')} (잔여 {remaining}일)"

# 도구 정보 확인
print(f"이름: {search_korean_law.name}")
print(f"설명: {search_korean_law.description}")
print(f"스키마: {search_korean_law.args}")
```

## 2. Pydantic 스키마 기반 도구

복잡한 입력 타입을 명확히 정의:

```python
from pydantic import BaseModel, Field
from langchain_core.tools import StructuredTool

class LegalSearchInput(BaseModel):
    query: str = Field(description="검색할 법령 키워드")
    law_type: str = Field(description="법령 종류: 민법/형법/상법/행정법", default="민법")
    max_results: int = Field(description="최대 결과 수", default=5, ge=1, le=20)

def legal_search(query: str, law_type: str = "민법", max_results: int = 5) -> str:
    """법령 검색 실행"""
    return f"[{law_type}] '{query}' 관련 조문 {max_results}개 검색됨"

# StructuredTool로 생성
legal_tool = StructuredTool.from_function(
    func=legal_search,
    name="legal_search",
    description="한국 법령과 판례를 검색합니다",
    args_schema=LegalSearchInput
)
```

## 3. BaseTool 상속 (완전 커스텀)

```python
from langchain_core.tools import BaseTool
from typing import Any

class CaseAnalysisTool(BaseTool):
    name: str = "case_analysis"
    description: str = "법률 사례를 분석하고 관련 판례를 검색합니다"

    def _run(self, case_description: str) -> str:
        """동기 실행"""
        # 분석 로직
        return f"사례 분석 완료: {case_description[:50]}..."

    async def _arun(self, case_description: str) -> str:
        """비동기 실행"""
        import asyncio
        await asyncio.sleep(0.1)  # 비동기 API 호출
        return self._run(case_description)

tool = CaseAnalysisTool()
```

## 4. 도구 에러 처리

```python
from langchain_core.tools import tool
from langchain_core.tools.base import ToolException

@tool
def fetch_court_decision(case_number: str) -> str:
    """법원 판결문을 가져옵니다."""
    if not case_number.startswith("20"):
        raise ToolException(f"잘못된 사건번호 형식: {case_number}. 연도로 시작해야 합니다.")

    # API 호출
    return f"판결문 {case_number}: ..."

# 에이전트에서 에러 처리 설정
from langchain.agents import AgentExecutor
executor = AgentExecutor(
    agent=agent,
    tools=[fetch_court_decision],
    handle_parsing_errors=True,  # 파싱 에러 처리
    max_iterations=5
)
```

## 5. 도구 설계 원칙

```
좋은 도구 설계:
✓ 이름: 명확하고 동사형 (search_law, calculate_deadline)
✓ 설명: LLM이 언제 사용할지 판단할 수 있게 구체적 작성
✓ 입력: 필요한 최소한의 파라미터
✓ 출력: 구조화된 텍스트 (JSON 또는 마크다운)
✓ 에러: 명확한 에러 메시지

나쁜 도구:
✗ 이름: "tool1", "function"
✗ 설명: "데이터 가져옴" (너무 모호)
✗ 입력: 너무 많은 옵션
✗ 출력: 원시 데이터 그대로 반환
```
