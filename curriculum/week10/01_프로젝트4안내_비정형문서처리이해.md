## 1. 📦 프로젝트 4: 기업 정보 분석 에이전트 소개

### 1.1 프로젝트 개요

**기업 정보 분석 에이전트(Enterprise Intelligence Agent)**는 상장기업의 공시 문서를 자동으로 수집, 처리, 분석하여 투자자, 애널리스트, 경영진이 신속하게 기업 정보에 접근할 수 있도록 하는 지능형 시스템입니다.

```

│                                                                    │
```

## 2. 🗂️ 비정형 데이터란?

### 2.1 데이터 유형 분류

데이터는 구조화 정도에 따라 세 가지로 분류됩니다.

```
데이터 구조화 스펙트럼
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
정형(Structured)  반정형(Semi-Structured)  비정형(Unstructured)
      │                    │                       │
      ▼                    ▼                       ▼
  관계형 DB              JSON/XML               텍스트 문서
  스프레드시트           HTML                   이미지
  CSV 파일               이메일                 오디오/비디오
  로그 데이터            NoSQL                  PDF (복합)
                                                프레젠테이션
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
명확한 스키마 ◄──────────────────────────► 스키마 없음
쉬운 처리    ◄──────────────────────────► 복잡한 처리
낮은 표현력  ◄──────────────────────────► 높은 표현력
```

### 2.2 비정형 데이터의 특성

**텍스트 (Text)**
- 자연어로 작성된 문서 (보고서, 기사, 이메일)
- 문맥, 감성, 의도 등 풍부한 정보 포함
- NLP 기술로 분석 가능

**이미지 (Image)**
- 사진, 스캔 문서, 차트, 다이어그램
- 픽셀 데이터 → CNN/Transformer로 분석
- OCR로 텍스트 추출 가능

**표 (Table)**
- 행/열 구조이지만 다양한 레이아웃으로 표현
- 병합 셀, 다단계 헤더, 계층 구조 존재
- 정형 데이터와 비정형 데이터의 경계

**차트 (Chart)**
- 막대, 선, 원형 등 다양한 형식
- 데이터를 시각적으로 표현
- 수치 추출이 기술적으로 어려움

### 2.3 정형 vs 반정형 vs 비정형 데이터 비교

| 특성 | 정형 데이터 | 반정형 데이터 | 비정형 데이터 |
|------|------------|--------------|--------------|
| 스키마 | 고정 스키마 | 유연한 스키마 | 스키마 없음 |
| 저장 방식 | RDBMS | NoSQL, 파일 | 파일 시스템, 객체 저장소 |
| 처리 도구 | SQL | XPath, JSONPath | NLP, CV, ML |
| 검색 방법 | 정확한 쿼리 | 구조적 쿼리 | 의미론적 검색 |
| 예시 | Oracle DB | MongoDB | PDF 보고서 |
| 정보 밀도 | 낮음 | 중간 | 높음 |
| 처리 난이도 | 낮음 | 중간 | 높음 |
| 전 세계 비율 | ~20% | ~15% | ~65% |

💡 **핵심 포인트**: 전 세계 데이터의 약 80%는 비정형 데이터입니다. 기업 문서의 대부분(보고서, 계약서, 이메일, 프레젠테이션)이 비정형 데이터에 해당하며, 이를 효과적으로 처리하는 것이 AI 서비스 경쟁력의 핵심입니다.

### 3.2 IR 보고서 구조

IR(Investor Relations) 보고서는 투자자 대상 기업 설명 자료로, 사업보고서보다 시각적 요소가 풍부합니다.

```
IR 보고서 특징
┌─────────────────────────────────────────────┐
│  텍스트 요소          시각적 요소            │
│  ┌─────────────┐    ┌─────────────────────┐ │
│  │ • 사업 현황  │    │ • 매출 성장 차트     │ │
│  │ • 전략 방향  │    │ • 시장 점유율 그래프 │ │
│  │ • 재무 요약  │    │ • 제품 로드맵 이미지 │ │
│  │ • 경쟁 우위  │    │ • 조직도             │ │
│  │ • 리스크     │    │ • 비교 표           │ │
│  └─────────────┘    └─────────────────────┘ │
│                                               │
│  레이아웃 복잡도: ★★★★★                       │
│  이미지 비율: 40~60%                          │
│  표 개수: 10~30개                             │
└─────────────────────────────────────────────┘
```

## 4. 🔄 비정형 문서 처리 파이프라인

### 4.1 전체 파이프라인 아키텍처

```
┌─────────────────────────────────────────────────────────────────┐
│              비정형 문서 처리 파이프라인                          │
└─────────────────────────────────────────────────────────────────┘

  입력 문서
  (PDF/DOCX/HTML)
       │
       ▼
┌─────────────┐
│  1. 수집     │  ← DART API, 웹 크롤링, 파일 업로드
│  (Ingest)   │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  2. 변환     │  ← PDF→이미지, DOCX→HTML, OCR 적용
│  (Convert)  │
└──────┬──────┘
       │
       ▼
┌─────────────┐    ┌──────────────────────────────┐
│  3. 파싱     │    │  파싱 결과:                   │
│  (Parse)    │───►│  • Title: 섹션 제목           │
│             │    │  • NarrativeText: 본문 텍스트 │
│             │    │  • Table: 표 데이터           │
│             │    │  • Image: 이미지 데이터       │
└──────┬──────┘    │  • ListItem: 목록 항목        │
       │            └──────────────────────────────┘
       ▼
┌─────────────┐
│  4. 정제     │  ← 노이즈 제거, 인코딩 정규화, 중복 제거
│  (Clean)    │
└──────┬──────┘
       │
       ▼
┌─────────────┐    ┌──────────────────────────────┐
│  5. 청킹     │    │  청킹 전략:                   │
│  (Chunk)    │───►│  • 제목 기반 청킹             │
│             │    │  • 고정 크기 청킹             │
│             │    │  • 의미론적 청킹              │
└──────┬──────┘    └──────────────────────────────┘
       │
       ▼
┌─────────────┐
│  6. 임베딩   │  ← 텍스트/표/이미지 벡터 생성
│  (Embed)    │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  7. 저장     │  ← 벡터 저장소 + 원본 청크 저장
│  (Store)    │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  8. 검색/생성│  ← RAG 체인으로 질의응답
│  (Retrieve) │
└─────────────┘
```

### 4.2 파이프라인 단계별 상세 설명

**단계 1: 수집 (Ingest)**
- DART Open API를 통한 자동 다운로드
- 기업코드 → 보고서 목록 조회 → PDF 다운로드
- 정기적 업데이트를 위한 스케줄러 구성

**단계 2: 변환 (Convert)**
- 스캔 PDF의 경우 이미지로 변환 후 OCR 적용
- 다양한 인코딩(EUC-KR, UTF-8) 처리
- 손상된 PDF 복구 시도

**단계 3: 파싱 (Parse)**
- `unstructured` 라이브러리로 Document Element 추출
- 레이아웃 분석으로 다단 컬럼 처리
- 표/이미지 좌표 정보 보존

**단계 4: 정제 (Clean)**
- 헤더/푸터 페이지 번호 제거
- 의미 없는 특수문자 정규화
- 동일 내용 중복 청크 탐지 및 제거

**단계 5: 청킹 (Chunk)**
- 섹션 구조 기반 청킹 (I. → 1. → 가. 계층)
- 재무제표 표는 섹션 단위로 유지
- 최대 토큰 수 제한 준수

## 5. ⚠️ 주요 도전 과제

### 5.1 레이아웃 복잡성

```
다단 레이아웃 문제 예시:
┌──────────┬──────────┐
│ 텍스트 A │ 텍스트 B │  ← 2단 레이아웃
│ 계속...  │ 계속...  │
├──────────┴──────────┤
│    표 (전체 폭)      │  ← 전체 폭 표
└─────────────────────┘

잘못된 파싱:
"텍스트 A 텍스트 B 계속... 계속..."
→ 두 컬럼이 혼합되어 의미가 왜곡됨

올바른 파싱:
"텍스트 A 계속..."
"텍스트 B 계속..."
→ 각 컬럼을 독립적인 블록으로 처리
```

### 5.2 OCR 오류

| 오류 유형 | 예시 | 해결 방법 |
|-----------|------|----------|
| 숫자 혼동 | 0→O, 1→I, 6→G | 후처리 규칙 적용 |
| 한글 오인식 | 삼성→삼썽 | 사전 기반 교정 |
| 표 구조 파괴 | 셀 경계 미인식 | 구조 기반 OCR |
| 저해상도 | 흐릿한 텍스트 | 이미지 전처리 |

### 5.3 표 파싱 어려움

```
복잡한 표 구조 예시:

┌──────────┬──────────────────────────────┐
│ 구분      │ 제21기 (2023)                │
│           ├──────────┬────────┬─────────┤
│           │ 1분기    │ 2분기  │ 연간    │
├──────────┼──────────┼────────┼─────────┤
│ 매출액    │ 10,000   │ 12,000 │ 45,000  │
├──────────┼──────────┼────────┼─────────┤
│ 영업이익  │  1,500   │  1,800 │  7,200  │
└──────────┴──────────┴────────┴─────────┘

도전 과제:
1. 병합 셀 처리 ("제21기 (2023)" → 3개 열에 걸침)
2. 다단계 헤더 처리
3. 소수점/단위 일관성 유지
```

### 6.2 unstructured 라이브러리 특징

`unstructured`는 Unstructured.io에서 개발한 오픈소스 라이브러리로, 다양한 문서 형식을 일관된 인터페이스로 처리합니다.

**핵심 장점**:
1. **통합 인터페이스**: PDF, DOCX, HTML, PPTX 등 20+ 포맷 지원
2. **Document Elements**: Title, NarrativeText, Table 등 의미론적 타입 분류
3. **레이아웃 분석**: `detectron2` 기반 고정밀 레이아웃 인식
4. **메타데이터 보존**: 페이지 번호, 좌표, 출처 정보 자동 추출
5. **클라우드 API**: 확장 가능한 서버리스 파싱 서비스 제공

### 6.3 도구 선택 가이드

## 8. 💻 실습: 기본 문서 분석

```python
# 기본 문서 분석 예제 (개념 이해용)
from pathlib import Path
import json

# 비정형 문서의 구성 요소를 딕셔너리로 시뮬레이션
sample_business_report = {
    "document_type": "사업보고서",
    "company": "삼성전자",
    "fiscal_year": 2023,
    "sections": [
        {
            "section_id": "I",
            "title": "회사의 개요",
            "element_type": "Title",
            "subsections": [
                {
                    "section_id": "I-1",
                    "title": "회사의 개요",
                    "element_type": "Title",
                    "content": [
                        {
                            "type": "NarrativeText",
                            "text": "당사는 1969년 설립된 세계적인 전자기업으로...",
                            "page": 5
                        },
                        {
                            "type": "Table",
                            "html": "<table><tr><th>구분</th><th>내용</th></tr>...</table>",
                            "page": 6
                        }
                    ]
                }
            ]
        },
        {
            "section_id": "III",
            "title": "재무에 관한 사항",
            "element_type": "Title",
            "subsections": [
                {
                    "section_id": "III-1",
                    "title": "연결재무제표",
                    "element_type": "Title",
                    "content": [
                        {
                            "type": "Table",
                            "caption": "재무상태표",
                            "html": "<table>..재무 데이터..</table>",
                            "page": 45
                        }
                    ]
                }
            ]
        }
    ]
}

def analyze_document_structure(doc: dict) -> dict:
    """문서 구조 분석 함수"""
    stats = {
        "total_sections": 0,
        "element_types": {},
        "tables_count": 0,
        "text_count": 0,
    }

    def traverse(sections):
        for section in sections:
            stats["total_sections"] += 1
            if "content" in section:
                for element in section["content"]:
                    elem_type = element["type"]
                    stats["element_types"][elem_type] = \
                        stats["element_types"].get(elem_type, 0) + 1
                    if elem_type == "Table":
                        stats["tables_count"] += 1
                    elif elem_type == "NarrativeText":
                        stats["text_count"] += 1
            if "subsections" in section:
                traverse(section["subsections"])

    traverse(doc["sections"])
    return stats

stats = analyze_document_structure(sample_business_report)
print(f"총 섹션 수: {stats['total_sections']}")
print(f"요소 유형별 분포: {json.dumps(stats['element_types'], ensure_ascii=False)}")
print(f"표 개수: {stats['tables_count']}")
print(f"텍스트 블록 수: {stats['text_count']}")
```
